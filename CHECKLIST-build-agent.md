# Чек-лист: збери Meeting Notes агента за 7 етапів

Іди по порядку. Біля кожного етапу - типові помилки і як їх лагодити. Усі граблі тут - реальні, я на них наступав.

---

## Етап 0. Що тобі треба (1 раз)

- [ ] Акаунт **n8n** (cloud від ~$20/міс АБО self-hosted безкоштовно через Docker)
- [ ] **DeepInfra API key** (deepinfra.com → API keys). Поповни на $5 - вистачить надовго
- [ ] **OpenAI API key** (platform.openai.com → API keys). $5 теж вистачить
- [ ] **ClickUp API token** (Settings → Apps → API Token) АБО **Jira** (email + API token)
- [ ] Один запис дзвінка mp3/m4a (бери зі `sample-data/`, якщо свого нема)

> **Скільки це коштує на потоці:** розпізнавання - найдешевша частина, годинний дзвінок коштує центи. LLM-обробка транскрипта дорожча за саме розпізнавання, і теж копійчана на gpt-4o-mini. Для 20-30 дзвінків на тиждень - одиниці доларів на місяць.

---

## Етап 1. Імпорт workflow

- [ ] n8n → Workflows → **Import from File** → обери `workflow-meeting-notes-clickup.json` (або `-jira.json`)
- [ ] Побачиш 8 нод: Form Trigger → Set (Team) → HTTP (DeepInfra) → Basic LLM Chain (+ OpenAI Chat Model + Structured Output Parser знизу) → Split Out → IF → ClickUp / Telegram

> **⚠️ Якщо AI-нод немає в списку:** твоя версія n8n стара. Онови до 1.50+ (langchain-ноди зʼявились там).

---

## Етап 2. Підключи ключі

### DeepInfra (нода Transcribe)
- [ ] Відкрий ноду **Transcribe (DeepInfra Whisper)**
- [ ] Credential → Header Auth → Name: `Authorization`, Value: `Bearer ТВІЙ_КЛЮЧ`

> **⚠️ Bearer забувають.** Значення саме `Bearer sk-...`, а не просто ключ. Без слова Bearer прилітає 401.

### OpenAI (sub-нода моделі)
- [ ] Відкрий sub-ноду **OpenAI Chat Model** (та, що знизу під chain)
- [ ] Credential → Create New → встав OpenAI key
- [ ] Модель: **gpt-4o-mini** (вже стоїть)

> **⚠️ Помилка #1 новачків:** шукають, куди вставити ключ, у ноді Basic LLM Chain. Ключ НЕ там. Він на sub-ноді **МОДЕЛІ**. 90% «чому 401» - саме це.

### ClickUp (нода виходу)
- [ ] Відкрий ноду **ClickUp** → Credential → API Token
- [ ] Постав свій `list_id` (як дістати - нижче)

---

## Етап 3. Список команди - найважливіший етап ⭐

Без нього агент бачить «Андрій» і не знає, кому призначати задачу. Із ним - мапить імʼя на конкретного виконавця в трекері.

- [ ] Відкрий ноду **Set: Team & Glossary**
- [ ] Заміни приклад на СВОЇХ людей: `імʼя` · `роль` · `user_id`
- [ ] Додай **словник проєкту**: 10-20 ваших термінів, назв модулів, прізвищ

### Як дістати ClickUp user_id
```
GET https://api.clickup.com/api/v2/list/{list_id}/member
Header: Authorization: ТВІЙ_ТОКЕН
```
Відповідь містить масив `members[]` з полями `id` (це і є user_id) та `username`.

### Як дістати list_id
Відкрий потрібний список у браузері. В URL: `.../v/li/901234567` → `901234567` це `list_id`.

### Як дістати Jira accountId
```
GET https://ТВІЙ-ДОМЕН.atlassian.net/rest/api/3/users/search
Auth: Basic (email + API token)
```

> **⚠️ Jira:** email як виконавця НЕ приймає - Atlassian сховав email за GDPR. Тільки `accountId` (виглядає як `5f8a1c2d9e4b00214a8c1f02`).

> **⚠️ Словник проєкту недооцінюють.** Це найдешевший спосіб підняти якість - дешевше за зміну моделі. Назви ваших модулів і прізвища розпізнаються криво без нього.

## Етап 4. Перевір промпт і схему

- [ ] Відкрий ноду **Basic LLM Chain** → промпт має містити текст із `prompt-extraction.md`
- [ ] Тумблер **«Require Specific Output Format»** = увімкнений
- [ ] Знизу підключена нода **Structured Output Parser** зі схемою з `output-schema.json`
- [ ] Переконайся, що в промпт підставляється список команди з ноди Set

Ключові правила, які МАЮТЬ бути в промпті (перевір, що вони на місці):
- [ ] фільтр «дія + виконавець + згода» - без усіх трьох це не задача
- [ ] заборона вигадувати виконавця → `owner: null`, якщо не визначено
- [ ] цитата з транскрипта на кожен action point
- [ ] якщо рішення переглядалось у дзвінку - брати ОСТАННЄ

> **⚠️ Хочеш свою схему:** режим parser **«Generate from JSON Example»**, встав приклад із `output-schema.json`, n8n сам виведе схему. Надійніше, ніж писати JSON Schema руками.

## Етап 5. Прожени перший дзвінок

- [ ] Активуй workflow (тумблер Active) АБО **Test workflow** → відкрий посилання форми
- [ ] Завантаж запис (візьми `sample-data/` якщо свого нема) → вибери проєкт → Submit
- [ ] Дивись результат по кроках

Маєш побачити:
- [ ] транскрипт приїхав (сирий текст із таймкодами)
- [ ] парсер віддав структуру: `action_points` / `decisions` / `risks`
- [ ] IF розкидав: впевнені пішли в трекер, сумнівні - на підтвердження
- [ ] у ClickUp зʼявились задачі з виконавцями, дедлайнами і цитатою в описі

### ⚠️ Транскрибація не працює
- **Порожній файл на виході** → у Body ноди HTTP вибрано не те. Треба **n8n Binary File** і правильне імʼя бінарного поля (за замовчуванням `data`), а не текстова вставка.
- **Таймаут на довгому файлі** → для дзвінків довше ~40 хв ріж на частини або тисни аудіо в **моно 16 кГц**. Якість розпізнавання від цього не падає, вага падає в рази.
- **401** → немає слова `Bearer` перед ключем.

### ⚠️ Парсер падає
- **«Could not parse output»** → модель повернула не чистий JSON (зайвий текст або ```-огорожі).
  **Fix 1:** додай **Auto-fixing Output Parser** - робить ще один прохід і лагодить.
  **Fix 2:** переконайся, що в промпті є слово «JSON».
  **Fix 3:** спрости схему, прибери частину обовʼязкових полів.
- **Вихід читається як `undefined`** → парсер кладе все під ключ `output`. Звертайся `{{ $json.output.action_points }}`, не `{{ $json.action_points }}`.

### ⚠️ ClickUp відхиляє задачу
- **Assignee не приймається** → ClickUp чекає **числовий user id**, не імʼя і не email. Бери id зі списку команди (Етап 3).
- **Due Date не ставиться** → ClickUp чекає **Unix timestamp у мілісекундах**, а не `2026-07-31`. Конвертуй у ноді Set перед ClickUp. Це граблі №1 на цій інтеграції.
- **401/403** → токен не той або немає доступу до простору.
- **Створилась ОДНА задача з масивом усередині** → забув ноду **Split Out** перед IF. Без неї весь масив летить одним айтемом.

### ⚠️ Jira відхиляє задачу
- **Assignee** → тільки `accountId`, не email (GDPR).
- **duedate** → формат `YYYY-MM-DD` (на відміну від ClickUp, тут НЕ timestamp).
- **Issue Type** → має існувати в проєкті. `Task` є не завжди, буває тільки `Story` / `Bug`.

## Етап 6. Контрольний тест чесності ⭐

Найважливіша перевірка. Агент, який чесно нічого не знайшов, кращий за агента, який насипав сміття.

Візьми `sample-data/call-script-ua.md` - там 7 навмисних пасток. Перевір по кожній:

- [ ] **Ідея без згоди** («колись би нам аналітику прикрутити») → задачі НЕ створено взагалі
- [ ] **Питання без відповіді** («а можна в понеділок?») → на підтвердження, дедлайн НЕ вигаданий
- [ ] **Рішення без дії** («поки лишаємо як є») → у `decisions`, не в задачах
- [ ] **Неоднозначний виконавець** (два Сергії) → `owner: null`, на підтвердження
- [ ] **Клієнт передумав** (Excel → PDF) → задача на PDF, Excel у `decisions`
- [ ] **Ризик** («без ключа на демо не вийдемо») → у `risks`, не в задачах
- [ ] **Чиста задача** (ключ, Андрій, пʼятниця) → у трекері, `confidence: high`

**Якщо агент насипав задач із пасток:**
- посили фільтр у промпті: «жодної задачі без дослівної цитати з транскрипта»
- додай явно: «ідея без згоди учасників - НЕ задача»
- додай: «якщо не впевнений у виконавці - `owner: null`, не вгадуй»

> У 9 із 10 випадків проблема в промпті, а не в моделі. Не міняй gpt-4o-mini на щось дорожче, поки не довів промпт.

## Етап 7. Увімкни гейт правильно

- [ ] Перші **два тижні** тримай усе в draft-режимі: IF відправляє ВСЕ на підтвердження PM, у трекер не пише нічого
- [ ] Дивись, де агент помиляється на ТВОЇХ дзвінках, дотягуй промпт і словник
- [ ] Тільки потім вмикай гібрид: `confidence: high` + виконавець визначений → у трекер

> **⚠️ Найдорожча помилка впровадження:** увімкнути повний авто одразу. Один раз агент насипле команді сміттєвих задач - і вам більше не дадуть його ввімкнути, навіть коли ви його доведете. Довіра команди дорожча за тиждень економії.

## Шпаргалка граблів (усе в одному місці)

| Симптом | Причина | Fix |
|---|---|---|
| 401 на транскрибації | немає `Bearer` перед ключем | `Bearer sk-...` |
| Порожній файл у DeepInfra | не n8n Binary File у Body | вибрати бінарне поле `data` |
| 401 на LLM | ключ шукали в chain | ключ на sub-ноді МОДЕЛІ |
| Could not parse output | модель віддала не JSON | Auto-fixing Output Parser |
| `undefined` у виразі | забули `output.` | `$json.output.action_points` |
| Одна задача з масивом | немає Split Out | додати перед IF |
| ClickUp: assignee не той | передали імʼя | числовий `user_id` |
| ClickUp: дата не ставиться | передали `YYYY-MM-DD` | Unix timestamp у **мс** |
| Jira: assignee не той | передали email | `accountId` |
| Виконавці не мапляться | немає списку команди | заповнити ноду Set (Етап 3) |
| Терміни розпізнаються криво | немає словника проєкту | додати 10-20 термінів |
| 25 задач із одного дзвінка | слабкий фільтр у промпті | «дія + виконавець + згода» |
