# Список команди + словник проєкту

Заповни СВОЇМИ даними і встав у ноду **Set: Team & Glossary**. Це найважливіші 15 хвилин усієї зборки.

> **Чому це критично.** Без списку команди агент бачить «Андрій» і не знає, кому призначати задачу - вигадує або лишає порожнім. Без словника ваші модулі й прізвища розпізнаються криво. Це найдешевший важіль якості - дешевше за зміну моделі.

---

## 1. Список команди → поле `team`

Формат - JSON-рядок. Заповни своїми людьми:

```json
[
  {"name": "",  "role": "", "id": ""},
  {"name": "",  "role": "", "id": ""},
  {"name": "",  "role": "", "id": ""}
]
```

**Що куди:**

| Поле | Що це | Звідки взяти |
|---|---|---|
| `name` | Імʼя і прізвище, як їх називають на дзвінках | з голови |
| `role` | Роль - Backend / Frontend / QA / Design / PM | з голови |
| `id` | user_id у трекері | див. нижче |

### Як дістати user_id

**ClickUp:**
```
GET https://api.clickup.com/api/v2/list/{list_id}/member
Header: Authorization: ТВІЙ_ТОКЕН
```
У відповіді - масив `members[]`, бери поле `id`.

**Jira:**
```
GET https://ТВІЙ-ДОМЕН.atlassian.net/rest/api/3/users/search
Auth: Basic (email + API token)
```
Бери `accountId` (виглядає як `5f8a1c2d9e4b00214a8c1f02`). Email не підійде - Atlassian сховав його за GDPR.

### ⚠️ Однакові імена

Якщо в команді два Сергія або дві Ірини - **вкажи це явно**, роль допоможе агенту розрулити:

```json
[
  {"name": "Сергій Кравець", "role": "Frontend", "id": "8244"},
  {"name": "Сергій Мельник", "role": "QA",       "id": "8249"}
]
```

Коли в дзвінку звучить просто «Сергій» без прізвища - агент має повернути `owner: null` і відправити задачу на підтвердження, а не вгадувати. Якщо ж контекст задачі явно фронтендний, він мапить на Кравця за роллю.

## 2. Словник проєкту → поле `glossary`

Простий текст, один термін на рядок: `термін - пояснення`.

**Що обовʼязково внести (10-20 рядків):**

| Категорія | Приклади |
|---|---|
| Назва проєкту і продукту | `Мережа Права - платформа документообігу` |
| Назви модулів | `експорт - модуль вивантаження документів у PDF` |
| Внутрішній сленг | `контур - середовище (тестовий контур = staging)` |
| Скорочення | `рев'ю - code review` |
| Прізвища клієнта | `Савченко - Дмитро Савченко, Product Owner з боку клієнта` |
| Підрядники й сервіси | `платіжка - інтеграція з payment gateway` |

**Шаблон для заповнення:**

```
# Проєкт і продукт
 - 

# Модулі та компоненти
 - 
 - 

# Внутрішній сленг і скорочення
 - 
 - 

# Люди з боку клієнта
 - 

# Зовнішні сервіси й підрядники
 - 
```

## 3. Як зрозуміти, що словник треба доповнити

Прожени 2-3 своїх дзвінки і подивись на транскрипт (не на задачі, а на СИРИЙ текст). Шукай:

- назви ваших модулів, записані фонетично криво
- прізвища, перетворені на випадкові слова
- англійські терміни, записані кирилицею навпіл
- сленг, який модель «виправила» на літературне

Кожне таке місце → рядок у словнику. Після 2-3 ітерацій словник стабілізується.

> **Практична порада:** тримай словник у цьому файлі, а не тільки в ноді n8n. Коли будете міняти workflow або збирати другого агента - скопіюєте готове, а не збиратимете заново.
