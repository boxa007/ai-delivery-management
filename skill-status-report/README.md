# Скіл status-report

Агент, який бере дані проєкту за тиждень і пише готовий статус-звіт клієнту. Трек Б домашки-хакатону.

---

## Установка (1 хвилина)

Скопіюй папку скіла в свій проєкт:

```bash
mkdir -p .claude/skills
cp -r skill-status-report .claude/skills/status-report
```

Перевір, що Claude Code його бачить:
```
/status-report
```

Якщо скіла немає в списку - перезапусти сесію Claude Code.

---

## Запуск без трекера (найшвидший старт)

Не потрібні ключі. Бери демо-дані з роздатки:

```
/status-report

→ проєкт: Мережа Права, період 15-22 липня
→ звідки дані: вставлю текстом
→ [вставляєш вміст sample-data/project-data.md]
```

Агент видасть готовий звіт у чаті.

---

## Запуск із трекером

### ClickUp
```bash
export CLICKUP_TOKEN="pk_..."      # Settings → Apps → API Token
export LIST_ID="901234567"          # з URL списку: .../v/li/901234567
```

### Jira
```bash
export JIRA_EMAIL="ти@компанія.com"
export JIRA_TOKEN="..."             # id.atlassian.com → API tokens
export JIRA_DOMAIN="компанія.atlassian.net"
export PROJECT_KEY="DEL"
```

Далі просто `/status-report` - скіл сам спитає проєкт і період і сходить у трекер.

---

## Що перевірити на першому прогоні

Скіл має знайти **сам**, без підказок:

- [ ] задачі, що переїхали, і чи поставлена нова оцінка
- [ ] переїзд **зі зміною скоупу** без переоцінки (найтонше)
- [ ] системне заниження оцінок по ролі або типу задач
- [ ] блокер, звʼязаний із найближчою віхою

На демо-даних `sample-data/project-data.md` закладені всі чотири. Якщо агент знайшов менше трьох - у нього замало вхідних даних (скоріш за все, не дав дані за минулий тиждень).

---

## Контрольний тест чесності

Прибери з вхідних даних блок «Задачі минулого тижня» і прожени ще раз.

**Правильно:** «база для порівняння за попередній період відсутня, динаміку не наведено».

**Неправильно:** бадьоре «на 20% швидше, ніж минулого тижня». Якщо побачив таке - у SKILL.md ослабло правило 1, посили формулювання.

---

## Зв'язок із Meeting Notes агентом

Два агенти складаються в петлю:

```
дзвінок → [Meeting Notes агент] → задачі в трекері
                    ↓
            decisions + risks
                    ↓
тиждень роботи → [status-report] → звіт клієнту
```

Вихід першого (`decisions`, `risks`, `client_asks`) - вхід другого. Саме тому звіт знає ПРИЧИНИ переїздів, а не тільки факт.

Можна користуватись і окремо: status-report працює по самому трекеру, просто блок «Рішення тижня» буде порожнім.
