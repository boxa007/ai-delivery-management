# AI-агенти для Delivery Management

**Meeting Notes агент:** запис дзвінка → транскрипт → action points → задачі в трекері з виконавцями.
**Агент звітів:** дані проєкту за тиждень → готовий статус-звіт клієнту.

Роздатка до уроку «AI-агенти для Delivery Management: різниця між простою транскрибацією та агентом, який розподіляє завдання».

## Навіщо це

Транскрипт віддає вам роботу. Агент виконує роботу.

У вас уже може стояти Fireflies або Otter. Вони добре роблять транскрипт і навіть action items. Але останній крок - призначити конкретного виконавця в конкретному списку вашого проєкту - все одно робить PM руками, бо інструмент не знає вашу команду, ваш трекер і ваші правила.

Цей репозиторій закриває саме цей останній крок.

| Сходинка | Що отримуєте | Що ще робите руками |
|---|---|---|
| Запис | mp3-файл | усе |
| Транскрипт | 40 сторінок тексту | читати, виділяти, ставити |
| Самарі | 1 сторінка переказу | виділяти дії, ставити |
| Action points | список рішень і дій | призначати, ставити |
| **Агент** ⭐ | **задачі в трекері з виконавцями** | **перевірити і підтвердити** |

## Швидкий старт (7 кроків)

1. **n8n:** імпортуй [`workflow-meeting-notes-clickup.json`](workflow-meeting-notes-clickup.json) (Workflows → Import from File). Для Jira - [`workflow-meeting-notes-jira.json`](workflow-meeting-notes-jira.json).
2. **DeepInfra:** [deepinfra.com](https://deepinfra.com) → API keys → встав токен у ноду **Transcribe**, Header Auth: `Authorization` = `Bearer ТВІЙ_КЛЮЧ`.
3. **OpenAI:** встав ключ у sub-ноду **OpenAI Chat Model** (НЕ в chain - помилка #1).
4. **ClickUp:** Settings → Apps → API Token. Там же візьми `list_id`.
5. **Команда:** відкрий ноду **Set: Team & Glossary** → заміни приклад на своїх людей ([шаблон](team-glossary-template.md)).
6. **Запусти:** відкрий форму → завантаж запис дзвінка → Submit.
7. **Перевір чесність:** фраза-ідея без згоди («колись би нам...») НЕ має стати задачею.

Детально кожен крок з усіма граблями → [**CHECKLIST-build-agent.md**](CHECKLIST-build-agent.md)

## Архітектура

```
[Form Trigger: файл дзвінка + проєкт]
        ↓
[Set: Team & Glossary]              ← список команди + словник
        ↓
[HTTP → DeepInfra Whisper large-v3] ← транскрипт + таймкоди
        ↓
[Basic LLM Chain + gpt-4o-mini]
   └── Structured Output Parser     ← action_points / decisions / risks
        ↓
[Split Out] → [IF: confidence high?]
   ├── так  → [ClickUp / Jira]      ← задача з виконавцем і цитатою
   └── ні   → [на підтвердження PM]
```

**Головний принцип:** рушій розпізнавання і трекер - змінні деталі на краях. Мозок посередині не змінюється. Хочеш ElevenLabs замість Whisper - міняєш одну ноду. Хочеш Jira замість ClickUp - міняєш одну ноду.

## Whisper чи ElevenLabs

| Ваша ситуація | Рушій |
|---|---|
| Чиста українська / англійська, добрий мікрофон | **Whisper на DeepInfra** (дешевше) |
| Суржик, кілька людей у кімнаті, треба розділення спікерів | **ElevenLabs Scribe** (стабільніше тримає змішане мовлення) |
| NDA-проєкт, дані не мають виходити з контуру | **self-host Whisper** (GPU + DevOps) |

На чистій українській Whisper `large-v3` тримає впевнено. На суржику починає «визначатись» із мовою: найгірше - коли він не помиляється у звуках, а **виправляє мовця**, записуючи літературну форму замість почутої. Для розпізнавання наче добре, для цитати-доказу вже не те, що людина сказала.

> Це оцінка з прогонів на реальних дзвінках, не лабораторний бенчмарк. Візьміть [sample-data](sample-data/) і прожените обидва рушії - послухайте своїми вухами.

**Ціна:** розпізнавання - найдешевша частина пайплайну, годинний дзвінок коштує центи. LLM-обробка транскрипта дорожча за саме розпізнавання, і теж копійчана на gpt-4o-mini.

## Що робить агента чесним

Три механізми, без яких він перетворюється на генератор сміття:

**1. Фільтр «дія + виконавець + згода».** Пункт стає задачею тільки якщо виконані всі три умови. Наївний агент робить 25 задач із дзвінка на 40 хвилин, робочий - 5-7.

**2. Цитата-доказ на кожну задачу.** Немає дослівної цитати з транскрипта - немає запису. Виконавець відкриває задачу і бачить точні слова клієнта, а не «PM щось вигадав».

**3. Гейт за впевненістю.** `confidence: high` + виконавець визначений → у трекер. Усе інше → на підтвердження PM. Неоднозначний виконавець (два Сергія в команді) → `owner: null`, а не вгадування.

> **Перші два тижні тримайте все в draft-режимі.** Один раз агент насипле команді сміттєвих задач - і вам більше не дадуть його ввімкнути, навіть коли ви його доведете. Довіра команди дорожча за тиждень економії.

## Приватність

Запис дзвінка = персональні дані.

- **Згода на запис** - вмикайте вбудоване сповіщення Zoom/Meet/Teams, не покладайтесь на «всі й так знають»
- **Перевірте договір із клієнтом** щодо передачі даних третім сторонам, ПЕРЕД першим прогоном реального дзвінка
- **NDA-проєкт** → або self-host Whisper у своєму контурі, або цей проєкт не автоматизуємо. Третього немає
- **Строк зберігання** - транскрипт і задачі тримайте, сирий запис за політикою, не «вічно про всяк випадок»

Спитати можна завжди, повернути назад передані дані - ні.

## Домашка-хакатон

| Трек | Що робиш | Складність |
|---|---|---|
| **A · Нотатки після дзвінка** | запис → action points → задачі у твій трекер | 🟢 easy - готовий workflow тут |
| **B · Статус-апдейт клієнту** | дані проєкту за тиждень → звіт | 🟢 easy - готовий скіл тут |
| **C · Генерація SoW** | onboarding-дзвінок → чернетка SoW | 🟡 medium - свій промпт |
| **D · Risk tracking** | ризики з усіх дзвінків → таблиця + алерти | 🔴 hard - стан між прогонами |

Візьми **реальні дані** (2-3 справжні записи, можна обезличені), збери під свій кейс, прожени і перевір, що сміття НЕ стало задачами.

**Критерії:** працює (0-3) · чистота (0-3) · цитата на кожну задачу (0-2) · виконавці правильні (0-1) · реальні дані (0-1).
**Прохідний:** працює + не робить сміттєвих задач + цитує дзвінок.
